Technology stack

Services behind the deployment

Each service has a clear purpose. S3 stores the files; Amplify handles HTTPS website delivery.

01 / STORAGE

Amazon S3

Stores the static index.html file as an object in a cloud bucket.

02 / HOSTING

AWS Amplify

Publishes the website from S3 with an HTTPS-enabled amplifyapp.com address.

03 / ACCESS

Bucket Policies

Controls access to stored objects. The original S3 website endpoint was configured for public read access.

04 / FRONTEND

HTML + CSS

Creates a responsive static project page without a backend or database.

Deployment workflow

What I implemented

  1. Created a general-purpose S3 bucket in the Asia Pacific (Sydney) Region.
  2. Uploaded the static website's index.html file.
  3. Enabled S3 static website hosting and configured an index document.
  4. Configured public-read access for the original S3 website endpoint.
  5. Deployed the S3 website using AWS Amplify Hosting for HTTPS access.
  6. Verified the live deployment and documented the process in GitHub.
Key learning

EC2 vs. S3 hosting

In Module 02, I hosted a website on Amazon EC2 by installing Apache on a Linux virtual machine. In Module 03, I learned that a static website can be stored in Amazon S3 and published through AWS Amplify—without managing a server.

Project scope: This is a static website demonstration, not a full-stack application. It does not handle accounts, databases, or server-side business logic.
